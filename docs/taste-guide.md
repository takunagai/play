# 審美基準（taste-guide）

対話で作った 2 作品（prism-pop・heartburst）の制作中に、ユーザー（発注者）が評価した点と指摘した欠陥をまとめたもの。自律作品の企画・実装・合否判定の基準にする。

- 抽出元: 2 作品の制作会話ログ（ユーザーの発話）と各作品の `docs/process-log.md`
- 出典の書き方: 「作品名 Phase」。Phase は各作品の `docs/process-log.md` の章
- 1・2 節はユーザーが言ったことだけ（アシスタント側の自己評価は含めない）

## 1. ユーザーが評価した点

| 評価 | ユーザーの言葉（要約） | 出典 |
|---|---|---|
| 見た目が綺麗・音が心地よい・連続で弾ける爽快感 | 「綺麗だし、音も心地よい。連続で弾けるのは爽快感ある」 | prism-pop Phase 5 |
| 動きが滑らか（カクつかない）こと | 描画の最適化の後に「カクつきはなくなった」で承認 | heartburst Phase 5（ネイティブ版） |
| 溜め・解放・楽器・物語まで足した完成形 | 「満足。完成でよい」 | heartburst Phase 10-1 |

読み取れる好み: 「綺麗」「心地よい音」「繰り返したくなる爽快感」の 3 つがそろって合格。滑らかさは見た目と同格の条件で、カクつきは美観の欠陥として扱われる。

## 2. ユーザーが指摘した欠陥

| 作品 / 出典 | 症状 | 原因 | 直し方 |
|---|---|---|---|
| heartburst Phase 9 | 「動作はするが、感動や面白さがない」 | 溜めの段階性・解放前の間・音楽との同期・結果の蓄積・触る前の誘いといったゲームフィールが欠けていた | 爽快感・ゲーム性・楽器・物語の 4 軸で改良（Phase 9-1〜9-4）。スキルの `references/game-feel.md` で観点ごとに欠けを洗う |
| heartburst Phase 9-5 | 粒子が画面の矩形の形で堰き止められる（直線の縁・蝶ネクタイ形が見える） | 粒子の配置・回り込み・再流入がすべて画面の矩形基準 | 住む範囲を画面中心の真円（画面外まで伸びる半径）にし、出入りを画面外で行う |
| prism-pop Phase 5 | ロード直後の泡に枠があり、操作開始後の見た目と違う | 画質の自動昇格で、standard（太い虹色の線）から rich（シェーダ）へ描き方が変わっていた | standard を rich と同じ光学モデルで描き直し、画質の段が変わっても見た目をそろえる |
| prism-pop（浮遊生物の追加後） | PC は良いがスマホで浮遊生物が小さい | PC 基準の大きさをそのまま縦長画面に使っていた | 縦長画面（幅 < 高さ）だけ大きさを 2 倍にする（`CREATURE_PORTRAIT_SCALE`） |
| heartburst Phase 16 | 爆発の連鎖が一瞬で終わり、「N CHAIN」も読めない | 種が本波の到達とほぼ同時に誘爆していた | 連鎖を 16 分の拍に乗せて間隔を空け、1 つずつ弾ける |
| heartburst Phase 9-6・9-7 | スマホ（iPhone）で音が全く出ない | タッチは指を離した時にしか音声を解錠できないのに、押した時に `resume()` を呼んで待っていた | `resume()` を待たずに配線し、`pointerup` / `touchend` / `click` / `keydown` で再開する常駐リスナーを置く |
| heartburst Phase 9-8 | 音は出たが、ロード時に数秒の待ちが出た | 音源の一括合成・パターン層の読み込みを起動時にまとめて行っていた | 使う順に小分けで準備し、間に合わないときは簡易音で代える |

## 3. 自律作品の合否チェックリスト

web-designer が `pnpm verify` のスクリーンショット 4 枚（375px / 1280px × 導入画面 / 操作後）だけで判定する。すべて Yes で合格。1・2 節のユーザーの評価・指摘に加え、制作中に見つかった見た目の不具合も出典にしている。

1. 暗い背景の上に、濁った茶色・オリーブ色（低い不透明度の橙〜黄緑）が出ていないか ─ 出ていなければ Yes（prism-pop Phase 2 の設計判断・スキル pitfalls）
2. 導入画面と操作後で、主役の要素（泡・粒子など）の質感や描き方が別物に見えないか ─ 同じに見えれば Yes（prism-pop Phase 5）
3. 曲線的・有機的な要素が、画面の四辺に沿った直線で不自然に切られていないか ─ 切られていなければ Yes（heartburst Phase 9-5）
4. 375px で、主役の要素が小さすぎたり詰まりすぎたりせず、1280px と同じくらいの存在感で見えるか（prism-pop 浮遊生物の追加後）
5. 操作後のスクリーンショットで、操作の結果（波紋・破裂・変化）が画面に残って見えるか ─ 触った手応えが絵でわかれば Yes（heartburst Phase 9）
6. 派手な演出で画面が白飛びし、主役の要素が消えていないか ─ 消えていなければ Yes（heartburst Phase 9-1・9-2 の白飽和の不具合）
7. 導入画面のタイトル・案内文が背景に埋もれず、375px でも改行が崩れず画面内に収まっているか（prism-pop Phase 5）
8. 375px・1280px とも、ボタンや文字が互いに重なったり画面外にはみ出したりしていないか（heartburst Phase 11 の説明カード検証）
9. 原色の太い輪・単調なグラデーションなど、安っぽい描き方になっていないか ─ 淡い光・にじみ・透明感で描かれていれば Yes（prism-pop Phase 4 の rich の泡）
10. 画面全体が「綺麗」と言える統一感（色数を絞ったパレット・暗い背景に発光）を保っているか（prism-pop Phase 5・heartburst Phase 10-1 の評価）
