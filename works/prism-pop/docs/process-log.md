# Prism Pop ─ 制作記録

## Phase 0: アイデア具体化（2026-09-24）

- ウィザード 3 ラウンドで確定: 快感・連打 / 弾く・割る / 有機的グラデーション / ライム × バイオレット / ベル・マリンバ / リディアン / ウェブ / マウス・タッチ / ローカル
- お任せ → 提案: 参照イメージ「炭酸・シャボン玉の泡」、連打時は和声音 {1,3,5,#4,7} に絞る
- 作品名は候補 3 案から Prism Pop を選定
- 規模: 当初「リッチ（デスクトップ専用）」→ ユーザー要望でスマホ対応に変更。「標準で起動し、性能に余裕があれば自動でリッチへ昇格」の適応型にした

## Phase 1: 環境構築

- `pnpm create vite web --template vanilla-ts --no-interactive`（Context7 `/vitejs/vite` で手順を確認）→ Vite 8.3 / TypeScript 6.0 / p5 2.3.3
- p5 v2 は型定義を同梱（`exports["."].types`）。`@types/p5`（v1 用）は入れない

## Phase 2: 設計正本

- `docs/architecture.md` を作成
- 判断: リディアンの #4（B）は 5 度（C）と短 2 度でぶつかる。コンボのはしごは 1-3-5-7 の上に #4 を 1 オクターブ上で置く配置（Fmaj7#11 の開いた配置）にした（`music.ts` の `LADDER_VOICING`）
- 判断: 背景は暗いので、ライム（色相約 75°）を背景ブロブに使うと泥色になる（skill pitfalls）。ライムは泡の縁・しぶきなど明るい要素だけに使う
- 判断: rich の屈折は背景をテクスチャに描かず、`field.ts` の同じ式をシェーダ内で評価する（FBO 不要、2 段で同じ背景になる）
- 仮実装の `prism-engine.ts` は engine.ts と循環 import になるため、engine.ts からは `import type` のみにした（値 import だと TDZ で落ちる）

## Phase 3: 実装（並行委譲）

- 視覚・操作・画質判定 → sonnet サブエージェント / 音響エンジン → opus サブエージェント
- `music.ts`・`audio/engine.ts` はメインが先に作成し、両者の契約にした
- 視覚担当の追加: p5 2.3.3 の配布物には `types/` が含まれていなかった（package.json の `types` は存在しないファイルを指す）。`@types/p5` は v1 用で合わないため、使う API だけの `src/p5-shim.d.ts` で補った
- 音響担当: Node 上の偽 AudioContext で、resume() が解決しない環境・20 pop/秒 × 60 秒・ノードリーク 0 を確認

## Phase 4: 統合・自動検証（agent-browser、自前の Chrome）

- マウス: 最初の押下で `contextState=running`。12 連打で amp 0.20〜0.53、余韻は 3 秒で 0.007 まで減衰。fps 56〜60、draw 0.5ms 以下、エラー 0
- **見つけた不具合 1: 連打で泡が枯渇**。12 個割っただけで 25 → 3 個。補充が 80〜220ms に 1 個かつ画面外の下から湧き、見える位置まで 1〜2 秒かかっていた。→ 不足率に比例して間隔を詰め（最短 35ms）、不足率 30% 超では画面下側に小さく湧いて膨らむ（半径そのものを動かすのでレンダラ変更不要）。修正後、150ms 間隔 30 連打で泡は常に 9〜20 個、空振り 0
- 本物のタッチ（CDP `Input.dispatchTouchEvent`）: touchStart 後は suspended、touchEnd 後に running（仕様どおり）。2 本指で 2 個同時、なぞり 1 回で 3〜7 個、ページのスクロール 0
- CPU 4 倍スロットル: 読み込み直後の長いタスク 72ms × 1（p5 初期化）、タップ直後 0 件、fps 59
- 画質の自動判定: M2 Max で試行に合格して rich を保存。基準計測の起点はページ表示（導入画面中も泡は動く）とし、architecture.md を実装に合わせた
- **見つけた不具合 2: rich の泡が原色の太いドーナツ**。膜色を原色 cos で角度方向に何周も回し、リム帯が半径 55% から、`atan` 起点のノイズで ±180° に継ぎ目。→ 球 + Schlick フレネル + 膜厚 220〜760nm・3 波長の薄膜干渉に書き直し、厚みと破れは角度を使わない滑らかな関数にした。淡い虹色・明るい縁・窓の映り込みになり、draw 0.15ms
- 検証用に `__prismDebug()` へ amp・種類別の累計 pop 数・combo を追加、開発ビルドのみ `__prismBubbles()`（泡の座標）を公開
- 音量: 元が 13 だったため 40 への変更は即取り消した（検証は元音量のまま、音は headless のみ）

## Phase 5: 体感チューニング

- ユーザー評価（PC）: 「綺麗・音が心地よい・連続で弾ける爽快感がある」
- スマホ実機確認のため、開発サーバーを `--host 0.0.0.0` で LAN 公開（`http://<LAN IP>:5190/`）
- 導入画面にタイトル「Prism Pop」を追加（コピー「触れて、はじけさせて」は残す）。度数色 5 色を流れるグラデーションで文字に通し、`drop-shadow` で発光（文字色が透明なので text-shadow は使えない）。タイトル → コピーの順にふわっと出す。`prefers-reduced-motion` では動きなし。390px 幅で横スクロールなし
- ユーザー指摘:「ロード直後の泡に枠があり、開始後と違う」。原因は画質の自動昇格（standard のスプライト → 数秒後に rich のシェーダ）。standard は太い虹色の線で描いていた
  - standard のスプライトを rich と同じ光学モデル（球のフレネル・膜厚 220〜760nm・3 波長干渉・上が明るい環境光・窓の映り込み）で画素単位に焼くよう書き直し。rich の合成 `bg·(1−min(0.8,F)) + 反射` を source-over の `C·a + bg·(1−a)` で再現（a = max(反射の最大チャンネル, min(0.8,F))）
  - 膜の揺らぎは膜厚パターン違いの 2 枚を、1 枚目 source-over・2 枚目 lighter でクロスフェード（重みの和が 1）。旧実装は 2 枚目を上塗りして明るすぎていた
  - 焼き時間: 短辺 800px で 51ms → `Math.hypot` を `Math.sqrt` に置換・窓の層は映り込みの範囲だけ走査で 28ms。短辺 390px（スマホ）は 7.6ms。リサイズ時の焼き直しは 150ms デバウンス
  - 残る差: rich はその場の背景色を映すが、standard は背景の近似色（固定値）で焼くため、縁の虹色が rich よりわずかに控えめ
- 作業環境の落とし穴: rtk 経由の `pnpm exec tsc --noEmit` は壊れたグローバル tsc（mise の typescript 7.0.2）を呼んで exit 1 で落ちるのに「TypeScript: No errors found」と要約表示する。型チェックは `rtk proxy ./node_modules/.bin/tsc --noEmit` で実行し終了コードを見る（`pnpm build` 内の tsc はプロジェクトのものなので影響なし）
- 改名: プロジェクトのルートフォルダを `iab-smoke` → `prism-pop`、`web/package.json` の name を `web` → `prism-pop` に変更（`web/` サブフォルダ名はスキルの構成に合わせて維持）。スキルは絶対パスのシンボリックリンクなので影響なし。Claude Code の memory は新パス用のディレクトリへ複写
